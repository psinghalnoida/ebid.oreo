Trading — listing lifecycle, all four sale formats

A prospective seller applies per-tenant first. A listing then moves through approval once, and its sale event branches by format — each format gates on its own EMD consent step before a buyer can commit. Tender is the deepest branch: interest, eligibility, document publication, EMD logging, bidding, an observer-facing stakeholder link, and its own auction report.

flowchart TB
  APPLY["/tenants/{id}/apply-to-sell"] --> SELLREVIEW{"TSX reviews\npending-sellers"}
  SELLREVIEW -->|approve| CREATE
  SELLREVIEW -->|reject| APPLY

  CREATE["/listings/create"] --> SHOW["/listings/{id}"]
  SHOW --> SUBMIT["Submit for approval"]
  SUBMIT --> REVIEW{"TSX reviews"}
  REVIEW -->|approve| SALEEVENT["Sale event created"]
  REVIEW -->|reject| SHOW
  SHOW -.disputed condition.-> FLAGCBS["Flag CBS violation"]

  SALEEVENT --> DEFECT["Defect disclosure\nmandatory before Express approval"]
  DEFECT --> FORMAT{"Sale format"}

  FORMAT -->|"Easy / Buy-Now"| EMD1["EMD consent"] --> BID["Bid\n(grace period, H1/H2 standing)"]
  FORMAT -->|Negotiate| OFFER["Offer\nsubmit / accept / withdraw"]
  FORMAT -->|Express| EMD2["EMD consent"] --> PLEDGE["Pledge + Express bid\nno grace period"]
  FORMAT -->|Tender| INTEREST["Register interest"]

  INTEREST --> ELIG["Eligibility grant\nTSX"]
  ELIG --> DOCS["Publish documents"]
  DOCS --> TEMD["Log EMD"]
  TEMD --> TBID["Tender bid"]
  TBID --> STAKE["Stakeholder link\nobserver view"]
  TBID --> CLOSE["Close bidding\nTSX"]
  CLOSE --> TREPORT["Tender Auction Report"]

  SALEEVENT -.live sale.-> ESTOP["⚠ Emergency Stop\nTSX, any format"]

  BID --> WIN["Sale closes"]
  OFFER --> WIN
  PLEDGE --> WIN
  TREPORT --> WIN
  WIN --> SETTLE["Settlement →"]

Method

Three passes: a static-route sweep first (D-102), a deeper zone-by-zone sweep checking every dynamic-segment route's actual trigger inside its parent page's template rather than just static hrefs (D-103), then a coverage check of this document itself against payments, invoicing, the live ticker, and the landing page — which is what surfaced the missing Platform Ops zone and three trading sub-flows below.
  1. Extracted all 194 routes from Routes.php, grouped by controller into the nine zones above.
  2. Cross-referenced each against every href/form action in app/Views/.
  3. Manually resolved every route with zero direct matches by reading its controller and the pages around it.
  4. For each genuine gap, added the missing entry point, then re-verified with a real logged-in browser session and, where the action changes state (Emergency Stop, Dispute filing), a direct database check — not just an HTTP 200.
  5. Re-ran the full regression suite against a rebuilt database after every change.
  6. For the diagram-completeness check: confirmed /admin/dashboard already links all fourteen Platform Ops pages, and that apply-to-sell, EMD consent, and defect disclosure each already have a real href in a live view — grep-verified, not assumed.
